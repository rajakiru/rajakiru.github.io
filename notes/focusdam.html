FocusDAM: What Does a Vision-Language Model Know but Not Say?

Probing hidden representations for fine-grained, region-aware image descriptions.

Generative AI · Vision-Language Models · Representation Probing · Multimodal Learning

Project context: FocusDAM was developed as a team final project for Carnegie Mellon University's 10-423/623/723 Generative AI course (Fall 2025), where our team's work received recognition. The project explored techniques for improving an existing generative AI model through baseline replication, experimentation, and evaluation.

This write-up focuses on my individual contribution: developing the Region-Aware Rephraser (RAR), a lightweight probing module that extracts fine-grained visual attributes from a pretrained vision-language model's hidden representations.

View project code on GitHub →

01. Starting with Describe Anything

Our project began with NVIDIA's Describe Anything Model (DAM), a vision-language model designed to generate detailed descriptions of specific regions within images and videos.

Unlike traditional image captioning models that describe an entire scene, DAM allows users to specify a region using a point, bounding box, mask, or scribble and generates a description focused on that region.

For example, rather than describing an entire bedroom, we might want to know what a small table beside the bed looks like, including its color, material, or shape.

How does DAM work?

DAM combines a localized vision backbone with a multimodal language model.

Given an image and a binary mask identifying the target region, DAM processes both the full image and a focal crop of the selected area.

The full image provides scene-level context, while the focal crop preserves details that might otherwise be lost when processing smaller objects.

Its localized vision backbone uses mask-aware visual representations and gated cross-attention to combine information from both views. These fused visual features are then passed to a language model, which generates a region-specific caption autoregressively, one token at a time.

The architecture is particularly interesting because it tries to balance two competing requirements: preserving fine-grained details within a selected region while retaining enough global context to generate a coherent description.

For more details, see the original Describe Anything paper (ICCV 2025).

02. What Was Missing?

While exploring DAM, our team identified three recurring limitations in its generated descriptions:

  • Off-region leakage: The model occasionally described objects or background elements outside the selected region.
  • Vague attributes: Smaller objects were sometimes described using generic terms, omitting details such as color, material, shape, or texture.
  • Inconsistent descriptions: The model could produce descriptions with different levels of specificity across regions within the same image.

Our team explored different approaches to address these limitations. My work focused on the second problem: missing fine-grained attributes.

For example, DAM might correctly identify an object as a table but omit its color or shape.

This raised an interesting question:

What if the model already represents these visual details internally, but doesn't necessarily include them in its final caption?

Rather than immediately training the model to generate longer descriptions, I wanted to explore whether those missing attributes could be recovered from its internal representations.

03. Reproducing DAM: Datasets & Benchmarking

Before modifying the model, we needed a reliable baseline to understand how well DAM performed and whether our proposed changes actually improved it.

We used NVIDIA's official implementation and pretrained DAM-3B weights, evaluating the model in a zero-shot setting without modifying its parameters.

We also followed the datasets and evaluation protocols used in the original DAM work to make our comparisons meaningful.

The datasets

We evaluated the model using three datasets:

DatasetPurpose
Ref-L4Evaluate detailed descriptions of localized image regions
Flickr30k EntitiesEvaluate short region-level descriptions paired with bounding boxes
DLC-BenchEvaluate attribute correctness, region locality, and hallucination using human-verified questions

For Ref-L4, we used a uniformly sampled subset of 3,000 images to make evaluation computationally manageable.

How do we evaluate a generated caption?

We used two complementary approaches.

Traditional captioning metrics

We computed BLEU, METEOR, ROUGE-L, CIDEr, and SPICE, which measure different aspects of similarity between generated captions and reference descriptions.

One complication was that Ref-L4 contains detailed captions, while many of these metrics are designed around shorter reference descriptions.

Following DAM's evaluation protocol, we used GPT-4o-mini to summarize both the generated and reference captions into single sentences before computing the metrics. Flickr30k Entities already contains short phrases, so no summarization was needed.

LLM-as-a-Judge

Traditional captioning metrics don't necessarily tell us whether a description is visually correct.

A caption could include accurate attributes absent from the reference and still receive a lower similarity score.

To evaluate caption correctness more directly, we also used the LLM-as-a-Judge framework from DLC-Bench, adapting it to use GPT-4o.

DLC-Bench contains human-verified question–answer pairs that test two aspects of localized descriptions:

  • Positive questions: Does the caption correctly describe the selected region and its attributes?
  • Negative questions: Does the caption avoid mentioning objects or attributes outside the selected region?

This evaluation was particularly relevant because our methods targeted different failure modes: LocalityGuard addressed off-region leakage, while the Region-Aware Rephraser aimed to recover missing attributes.

With the baseline established, we could begin experimenting with improvements.

04. From Fine-Tuning to Probing

My initial direction was to explore parameter-efficient fine-tuning techniques, including LoRA and Prefix-Tuning, to encourage DAM to produce more attribute-rich descriptions.

In principle, these methods allow a pretrained model to be adapted without updating all its parameters.

However, integrating them into DAM proved challenging.

DAM's multimodal architecture introduced complications with preprocessing, decoder integration, and image-conditioned inference. We encountered recursion errors when integrating LoRA, unstable training under limited GPU memory, and difficulties applying the trained adapters during inference.

Our pilot experiments on approximately 1,000 images also failed to match the DAM-3B baseline under the training configurations we could support.

These constraints motivated us to explore another approach: probing the model's existing representations instead of modifying the model itself.

What is probing?

Probing is an established technique in neural network interpretability for investigating what information is encoded in a model's internal representations.

The basic idea is to freeze a pretrained model, extract its hidden states, and train a smaller classifier to predict some property of interest.

This approach was introduced in work such as Understanding Intermediate Layers Using Linear Classifier Probes (Alain & Bengio, 2016).

Rather than using probing solely for interpretability, I wanted to explore whether the information recovered from DAM's hidden states could be useful for improving its generated captions.

For example, if DAM generated a caption identifying an object as a table, could its hidden representations also contain recoverable information about the table's color, material, or shape?

Why choose probing over fine-tuning?

The main advantage for our project was that probing allowed us to keep DAM frozen and train a much smaller, independent module.

Instead of backpropagating through the 3B-parameter model, we could extract its hidden representations once and train a lightweight classifier on those features.

This made experimentation more manageable under our compute constraints and let us focus on a specific hypothesis: whether fine-grained visual attributes were recoverable from DAM's existing representations.

However, probing comes with an important limitation. Successfully predicting an attribute doesn't necessarily prove that the original model uses that information during caption generation. A sufficiently expressive probe may also learn relationships from the training data itself.

This distinction is discussed in Designing and Interpreting Probes with Control Tasks (Hewitt & Liang, 2019).

05. Building the Region-Aware Rephraser

I implemented the Region-Aware Rephraser (RAR) as a lightweight module attached to DAM.

The idea was to extract hidden representations during caption generation, predict visual attributes from those representations, and incorporate the predictions into the original caption.

DAM remained frozen throughout training. Only the RAR module was optimized.

Step 1: Extracting decoder hidden states

DAM generates captions autoregressively, predicting each new token conditioned on the image and previously generated tokens.

During generation, the model produces hidden representations at each decoder layer.

I extracted the final decoder layer's representation corresponding to the newly generated token at every decoding step.

For decoding step \(t\):

\[ h^{(t)}=h_L^{(t)}[0,-1,:]\in\mathbb{R}^{d} \]

where \(L\) represents the final decoder layer and \(d\) is the hidden-state dimension.

Collecting these representations across decoding steps produces a sequence of token-level hidden states:

\[ H=[h^{(1)},h^{(2)},\ldots,h^{(T)}] \]

Rather than relying on a single token representation, this allowed the probe to use information from the generated sequence.

In our implementation, hidden-state sequences were paired with ground-truth attributes and saved as PyTorch tensors, forming the probing dataset.

Step 2: Learning a region-level representation

The extracted hidden states form a variable-length sequence, since different captions contain different numbers of generated tokens.

To convert this sequence into a fixed-dimensional descriptor, RAR uses a RegionPooling module:

\[ z=\operatorname{Pool}(H)\in\mathbb{R}^{d} \]

Our implementation supported mean pooling, max pooling, last-token pooling, and attention-based pooling.

The learned pooling approach was intended to give greater importance to token representations relevant to attribute prediction, rather than treating every token equally.

For example, representations associated with nouns or descriptive adjectives might be more informative than those associated with function words.

The resulting vector acts as a compact semantic representation for attribute prediction.

Step 3: Predicting fine-grained attributes

The pooled representation is passed through a shared transformation layer:

\[ h=\operatorname{ReLU}(\operatorname{LayerNorm}(W_sz+b_s)) \]

The output is a 512-dimensional feature vector, which feeds four separate attribute classification heads:

Attribute categoryNumber of labels
Color19
Material12
Shape10
Texture11
Total52

Each head predicts attribute probabilities using sigmoid outputs.

We used multi-label classification because attributes are not necessarily mutually exclusive. An object can be white and brown, or smooth and glossy, at the same time.

Each attribute head is trained using binary cross-entropy, and the overall objective averages the losses across the four categories:

\[ \mathcal{L}=\frac{1}{|K|}\sum_{k\in K}\mathcal{L}_k \]

where \(K\) represents color, material, shape, and texture.

This architecture lets the model learn a shared feature representation while making category-specific predictions.

Step 4: Rephrasing the caption

At inference time, DAM first generates its original caption and hidden states.

RAR then predicts visual attributes from the extracted representations and uses a rule-based rephrasing step to incorporate them into the caption.

For example:

Original DAM caption:

"A small table beside the bed."

RAR-enhanced caption:

"A small white circular table beside the bed."

The goal was to preserve the original object's identity and context while adding potentially useful visual details.

An important limitation is that predicted attributes are not guaranteed to be visually correct. The probe may recover plausible associations rather than details grounded in the selected region.

This makes attribute correctness an essential part of evaluation.

06. Training & Compute Constraints

Our experiments were conducted using a combination of local GPU hardware and Google Colab Pro.

Most experiments used an RTX 3060-class GPU with approximately 8 GB of VRAM or A100 GPUs available through Colab.

We focused on DAM-3B because the larger DAM-8B model exceeded our available memory budget.

Building the probing dataset

For RAR, we curated 2,908 training examples from the Ref-L4 Objects365 subset, selecting small regions with rich attribute annotations.

For each example, we ran DAM to extract the final-layer decoder hidden states and paired those representations with the corresponding attribute labels.

These pairs formed the training dataset for our probe.

Training RAR

We trained the attribute classifier for 100 epochs, with each epoch taking approximately two minutes.

The reported training time was approximately 3.5 hours.

Because DAM remained frozen, we did not need to backpropagate through the entire pretrained model during probe training.

The training pipeline optimized the multi-label binary cross-entropy objective, tracked per-attribute precision, recall, and F1, and saved the best-performing model checkpoint.

Full evaluations across the three datasets took approximately five hours per evaluation run.

One of the biggest practical lessons from this process was that model selection isn't just about choosing the most powerful architecture.

It also depends on the available hardware, the complexity of integrating with an existing model, the quality of training data, and whether experiments can be reproduced and evaluated within a reasonable time.

Probing ultimately gave us a more manageable way to explore attribute extraction under those constraints.

07. Results: Did Probing Improve the Captions?

We evaluated RAR using both traditional captioning metrics and the DLC-Bench LLM-as-a-Judge framework.

The results were mixed across datasets, but the LLM-judge evaluation showed improvements in attribute-related correctness.

DLC-Bench: LLM-as-a-Judge
MetricDAM-3BDAM + RAR
Positive accuracy45.0%66.3%
Negative accuracy74.5%83.3%
Overall average60.1%74.8%

RAR improved positive-question accuracy by 21.3 percentage points over our replicated DAM-3B baseline.

This was particularly relevant to our objective because positive questions test whether a caption contains correct information about the selected region.

Negative-question accuracy also improved, suggesting that the additional attribute information did not necessarily come at the expense of locality under this evaluation.

However, these results reflect the specific judge-based evaluation setup and should not be interpreted as proof that every predicted attribute was visually correct.

Traditional captioning metrics

On Flickr30k Entities, RAR improved METEOR, ROUGE-L, CIDEr, and SPICE compared with our replicated DAM-3B baseline, while BLEU decreased.

On Ref-L4, however, all five traditional captioning metrics declined.

Why might this happen?

One possible explanation is the difference between the captions RAR generates and the references used for evaluation.

For example, suppose the reference caption is:

"A dog running."

RAR might generate:

"A brown and white dog running through the grass."

The second description contains more attributes, but traditional metrics may penalize the additional words because they don't appear in the reference.

This is especially relevant when evaluating detailed descriptions against short reference captions.

However, the decrease in scores could also reflect incorrect attribute predictions, unnecessary details, or changes in caption structure. The results alone don't distinguish between these possibilities.

What does a better caption actually mean?

This was one of the more interesting questions that emerged from our evaluation.

BLEU and ROUGE emphasize lexical overlap, CIDEr rewards consensus with reference descriptions, and SPICE evaluates semantic propositions such as objects, attributes, and relationships.

But none of these metrics independently verifies that every attribute in a generated caption is visually grounded in the selected region.

For a method like RAR, I think a more complete evaluation should consider three separate questions:

  1. Does the caption contain more useful attributes?
  2. Are those attributes visually correct?
  3. Does the description remain focused on the selected region?

These are related but distinct aspects of caption quality.

08. What I Learned

The most interesting part of FocusDAM for me was exploring the difference between what a model represents internally and what it ultimately generates.

Before this project, I had mostly approached improving generative models through prompting or fine-tuning.

Probing introduced me to another approach: extracting useful information from a pretrained model's internal representations and using it for a downstream task.

Implementing RAR gave me hands-on experience with hidden-state extraction, representation pooling, multi-label classification, and integrating a lightweight learned module into an existing generative pipeline.

It also made me think more carefully about engineering constraints.

We initially explored fine-tuning methods such as LoRA and Prefix-Tuning, but the combination of multimodal integration challenges and limited compute pushed us toward a different solution.

That shift was a useful reminder that the most appropriate method isn't always the most complex one. Sometimes the better engineering decision is to reuse existing representations and train a smaller, more targeted component.

Finally, the evaluation results reinforced how important it is to define what improvement actually means.

Adding more descriptive words is relatively straightforward. Ensuring those details are accurate, grounded in the image, and genuinely useful is a much harder problem.

If I revisited FocusDAM, I'd want to compare linear and nonlinear probes, examine representations from different decoder layers, and evaluate predicted attributes directly against visual ground truth.

More broadly, this project changed how I think about working with pretrained multimodal models. Their generated outputs are only one part of the system; the intermediate representations can also be useful building blocks for downstream applications.
